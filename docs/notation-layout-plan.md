# 譜面レイアウト改善 計画

## 1. 何が起きているか（実測）

Playwright で実ブラウザ（Chromium / iPhone 相当 390px 幅）を計測した結果。

### 1.1 根本原因：VexFlow に必要量の半分以下しか幅を与えていない

VexFlow 自身に `Formatter.preCalculateMinTotalWidth()` で「この小節を組むのに最低いくら要るか」を聞いた結果：

| 対象 | 必要な幅（ユーザー単位） |
|---|---|
| 小節1（8分 + 4分休 + 8分） | 167 |
| 小節2（4分休 + 8分 + 8分休） | 138 |
| 小節3（4分休 + 8分 + 8分休） | 138 |
| 小節4（8分 + 付点4分休） | 105 |
| 音部記号 + 拍子記号 | 78 |
| **4小節を1段に並べる合計** | **626** |

**現在の実装は `LOGICAL_WIDTH = 300` を渡している。** 必要量の 48%。

VexFlow は与えられた幅に収めようとして音符を詰め、収まらないぶんが偏る。
これが「詰まって右に寄る」「大きさがちぐはぐ」に見える原因。

### 1.2 グリフの大きさ自体は正しい

前回の pt→ユーザー単位の変換は**正しく効いている**。実測値：

| 項目 | 実測（CSS px） | ユーザー単位に換算 | 期待値 |
|---|---|---|---|
| 五線の高さ | 46.2 | 40.0 | 40（線間10×4） |
| 線間 | 11.6 | 10.0 | 10 |
| 符頭の幅 | 13.6 | 11.8 | 約11.8（1.18 × 線間） |

**グリフと五線の比率は VexFlow の設計どおり。** 残っていた問題は幅だけだった。

### 1.3 検証方法が間違っていた（これが最大の反省点）

これまで jsdom（vitest）で描画を確認していたが、**jsdom は canvas を持たないため
VexFlow が文字幅を測れない**。テスト実行時に `No context for txtCanvas` が
**3,619回**出ていた。

文字幅が測れないと Formatter の配置計算が実ブラウザと別物になる。
**私が「確認済み」と言って送っていたプレビューは、実機の見た目を表していなかった。**

→ Playwright + Chromium がこの環境に入っていることを確認済み。
　実ブラウザでの検証に切り替える。

### 1.4 縦のバランス

譜面の SVG は 127px しかないのに、`.stage` が `flex: 1` で縦の余りを全部吸っている。
結果、譜面の上下に大きな空白ができている。

## 2. 直す方針

### 2.1 幅は「ハードコードした数値」ではなく「VexFlow に聞いた値」から決める

固定値 300 を書いたのが誤り。手順を逆にする。

```
1. 各小節の最小幅を preCalculateMinTotalWidth() で取得する
2. 段組み（何小節ずつ折り返すか）を決める
3. 段ごとに「音部記号 + 拍子記号 + その段の小節の最小幅の合計」を求める
4. 論理幅 = 全段の最大値（＋余裕）
5. その論理幅で描き、viewBox で表示幅に合わせる
```

これなら**リズムが増えても、音符の多いパターンが来ても破綻しない。**

### 2.2 段組み：2小節 × 2段にする

1段に何小節入れるかで、画面上の大きさが決まる。

| 段組み | 必要な論理幅 | 390px 幅での表示倍率 | 五線の高さ |
|---|---|---|---|
| 4小節 × 1段 | 626 | 0.55 | 22px |
| **2小節 × 2段** | **383**（1段目 78+167+138） | **0.91** | **36px** |
| 1小節 × 4段 | 245 | 1.4 | 56px（大きすぎ・縦に長い） |

**2小節×2段を採る。** 五線の高さ 36px は、見本の the Clave（実測で 25〜30px 程度）
と同等かやや大きく、スマホで無理なく読める。

見本は1段だが、あちらは **2小節**（2/2）。こちらは同じ音楽を **4小節**（2/4）で
書いているため、1段に入れると1小節あたりの幅が半分になる。
**小節数が違うので、1段という見た目だけを真似ても同じにはならない。**

### 2.3 縦のバランス

- `.stage` に `flex: 1` を与えるのをやめ、譜面の高さに沿わせる
- 空いた縦方向は BPM 表示と再生ボタンに配分する

### 2.4 音部記号を出すかどうか

音部記号 + 拍子記号で 78 単位を使う。**うち音部記号が約 48 単位。**

見本の the Clave は**音部記号を出していない**（拍子記号のみ）。
打楽器の1声部だけを示す譜面では珍しくない書き方で、
外せば幅が 48 単位浮き、そのぶん音符を大きくできる。

→ **オーナー（奏者）に確認する。** 譜面としての正しさに関わる判断のため。

## 3. 再発を防ぐ仕組み

### 3.1 実ブラウザでの検証を仕組みに入れる

- Playwright で 390px 幅のスクリーンショットを撮る手順を `scripts/` に置く
- 変更のたびに実物を見てから報告する

### 3.2 テストで固定する

| 検証項目 | 方法 |
|---|---|
| 与える幅が VexFlow の最小要求以上 | `preCalculateMinTotalWidth()` と比較して assert |
| pt 単位が残っていない | 既存テストを維持 |
| グリフと五線の比率 | 既存テストを維持 |
| 音符が段からはみ出さない | 実ブラウザで座標を測って assert |

**jsdom のテストは「データの正しさ」までに責任範囲を限定し、
「見た目」は実ブラウザで検証する**と役割を分ける。

## 4. 作業の順序

1. `preCalculateMinTotalWidth` で必要幅を算出する仕組みを入れる（幅の固定値を廃止）
2. 2小節×2段の段組みにする
3. `.stage` の縦の吸い込みをやめ、余白を配分し直す
4. Playwright のスクリーンショット手順を `scripts/` に置く
5. 幅の下限をテストで固定する
6. 実ブラウザで確認してから報告する

## 5. オーナーへの確認事項

1. **音部記号を出すか**（見本の the Clave は出していない。外すと譜面が大きくできる）
2. **2小節×2段でよいか**（1段にすると音符が半分の大きさになる）
3. **小節線の様式**（見本は複縦線で始まり終わる。今は単線）
